# 拾链 v1.0.1 操作教程

作者：雪落a · B站 ID：雪落a77 · [个人网站](https://xueluo.online)

## 1. 下载、安装和启动

**推荐：[直接下载安装包 LinkHarbor-v1.0.1-Setup.exe](https://github.com/Xueluoa1/linkharbor/releases/download/v1.0.1/LinkHarbor-v1.0.1-Setup.exe)。**

1. 双击安装包，在简洁安装窗口中选择有写入权限的独立文件夹。默认安装到当前用户的 `%LOCALAPPDATA%\Programs\LinkHarbor`。
2. 按需勾选“创建桌面快捷方式”，点击“安装”。路径和勾选项会隐藏，原位置显示真实安装进度。
3. 等待安装完成，点击“启动拾链”。以后从桌面、开始菜单或安装目录内的 `拾链下载器.exe` 打开。
4. 安装过程中点击“取消”会请求停止并回滚，请等待处理结束。不要强制结束安装进程。
5. 安装包包含全部运行组件，无需另下 ZIP。系统要求：Windows 10/11 x64、.NET Framework 4.x。安装包约 92 MiB，程序约 300 MiB；安装位置至少保留 700 MB，并为系统临时目录留出空间。

安装版的设置位于 `%LOCALAPPDATA%\LinkHarbor\settings.json`；默认下载到用户“视频”目录下的“拾链”，也可在主界面选择其他目录。作者和网站入口保留在安装窗口底部。升级、迁移和卸载见第 11 节。

### 便携方式（可选）

发布页只保留安装包 EXE 和压缩包，旧自展开 EXE 与界面单文件 EXE 已移除。便携使用请选择 ZIP；已经下载旧自展开版的用户仍可继续运行展开目录中的主程序，保留整个目录即可。校验值见发布页。

ZIP 使用步骤：

1. 打开 [v1.0.1 正式版下载页](https://github.com/Xueluoa1/linkharbor/releases/tag/v1.0.1)。
2. 下载 `LinkHarbor-v1.0.1-Windows-x64.zip`。页面自动生成的 `Source code` 是源码，不能直接双击运行。
3. 将 ZIP **全部解压**到可写的目录，例如 `D:\Apps\LinkHarbor`；不要在压缩包内部运行，也不要只拖出 EXE。
4. 双击 `拾链下载器.exe`。首次启动不需要安装 Python、Node.js 或 Visual Studio。
5. 系统要求为 Windows 10/11 64 位、.NET Framework 4.x。程序为未签名的个人开源工具；如系统提示，请先核对下载来源和 SHA-256，不要关闭系统安全防护。

便携目录的主要内容：

```text
拾链下载器.exe       主程序，文件属性可查看 1.0.1 版本
tools/               yt-dlp、FFmpeg、Node.js 及随包 DLL，必须保留
使用说明.txt         离线快速说明
docs/使用教程.md     本教程
AUTHOR_NOTICE.md     作者声明与售卖倡议
LICENSE              拾链 GPL-3.0 许可证
THIRD_PARTY_NOTICES.txt
```

`下载/` 和 `settings.json` 会在使用时产生，不含在官方初始包中。目录应有写入权限；不要放在受保护的系统目录。

## 2. 单个视频下载

1. 在浏览器中打开目标视频，复制视频页面地址。
2. 回到拾链，在链接框按 `Ctrl+V` 粘贴。
3. 点击“解析链接”，等待标题和可选画质出现。
4. 选择“视频 + 音频”；选择“最佳可用画质”或清晰度上限。
5. 检查保存位置，必要时点击“更改位置”。
6. 点击“开始下载”，等待下载、合并和最终文件校验结束。
7. 显示完成后，点击“打开文件夹”查看成品。

画质选项是上限，不会把低清内容提升为高清。分离的音视频通常合并为 MKV；单文件来源保留来源格式，不保证输出一定是 MP4。

## 3. 批量下载与排队

在链接框中粘贴多个单视频地址，支持每行一个、英文分号 `;` 或中文分号 `；`：

```text
https://example.com/video-a
https://example.com/video-b
```

回车只换行，不会触发解析。重复链接会自动忽略。点击“解析链接”后，统一选择格式、画质和保存目录，再点击“开始下载”。最多同时运行 **3 项**，其余自动排队；某个链接失败不会中断其他任务。当前不处理频道、播放列表或进行中的直播。

每批任务共用代理和 Cookie 来源；不同网站需要不同登录信息时，建议分批处理并切换 Cookie 文件。

## 4. 仅下载音频

- **仅音频 · 原格式**：尽量保留源音频编码，输出扩展名由来源决定。
- **仅音频 · MP3**：通过 FFmpeg 转换，可能更耗时，且有损音频再次转码会损失质量。

选择音频模式后，视频画质选项禁用。无需另装 FFmpeg，便携版已经包含。

## 5. 任务弹窗、日志和进度

点击左侧下载图标打开任务弹窗，查看每项任务的状态、进度、速度、剩余时间和输出位置。选中任务可查看日志与失败原因。关闭任务弹窗不影响后台任务，再次点击可重开。

主界面总进度是各任务的平均估算，包含下载、合并/转换及最终文件确认；失败和取消不计为成功，全部成功后才到 100%。切换音视频流时，当前流的字节数可能变化，不等于任务重新开始。

“任务日志”显示详细诊断信息，关闭程序后内存日志清空。反馈问题时提供版本号、错误文字和复现步骤；不要公开 Cookie、账号凭据或私人视频链接。

## 6. 取消、重试、清空与重复文件

- 点击“取消全部”，停止运行和排队中的任务；已完成文件保留。
- 取消后可能保留 `.part` 等临时文件；重试相同内容时可尝试续传，具体取决于站点和来源。
- 已有同名完整文件通常会跳过；批量输出含链接短标识，减少同名冲突。
- 下载结束或取消后，重新解析所需链接，再下载以重试失败任务。
- 输入框旁“清除”用于清空链接和解析状态，不是删除磁盘文件。任务运行期间相关编辑控件会禁用。
- 下载中关闭主窗口会询问是否取消任务后退出。

## 7. 保存位置与设置

默认保存到程序旁的 `下载` 文件夹。点击“更改位置”选择有写入权限的目录；左侧文件夹图标可打开下载目录。

普通代理地址和保存路径存入 `settings.json`，Cookie 路径仅用于当前会话，带账号密码的代理地址不保存。若移动程序到另一台电脑，原保存路径可能不可用，需重新选择。

## 8. 代理设置

1. 在自己正在使用的代理软件中查找本地 **HTTP / Mixed** 监听地址和端口。
2. 在拾链“网络与登录”卡片填入地址，例如 `http://127.0.0.1:7890`。这里的 `7890` 只是示例，以自己的软件设置为准。
3. 使用 SOCKS5 时填写 `socks5://127.0.0.1:实际端口`；不需要代理时留空。
4. 重新解析链接。连接被拒绝时先确认代理软件已启动、端口及协议匹配。

这里不能填写订阅链接、远程节点端口或代理管理 API 地址。点击卡片中的“如何获取？”可查看内置说明。

## 9. Cookie 登录信息

部分站点会要求登录或“确认不是机器人”。你可以在自己的浏览器中登录目标网站，并通过可信扩展导出该网站的 **Netscape 格式 cookies.txt**，然后在拾链点击“选择 Cookie 文件”。具体扩展入口和说明在程序“如何获取？”的 Cookie / 浏览器插件页，以及根目录 `使用说明.txt` 中。

Cookie 相当于登录凭据：不要发给别人、上传仓库、随截图公开或放进分发包。只导出任务所需网站的信息。拾链不会自动读取浏览器登录数据；每个任务创建独立临时副本，用后清理，不修改原文件。不需要时点击“清除”，失效后重新登录并导出。

Cookie 和代理不能保证绕过站点验证，也不能赋予没有的观看或下载权限。

## 10. 常见问题

| 现象 | 排查方法 |
| --- | --- |
| 缺少 tools 中的程序或 DLL | 重新完整解压官方便携包，检查安全软件隔离记录，不要混用不同 FFmpeg 版本的 DLL |
| 无法运行 / 系统不兼容 | 确认 Windows 10/11 x64 和 .NET Framework 4.x；从源码构建不是普通用户的必需步骤 |
| 解析失败 | 检查是否单视频地址，查看日志，确认网络及代理；站点改版可能需要更新 yt-dlp |
| 登录或反机器人验证 | 按第 9 节选择自己的有效 Cookie；仍失败时以站点验证结果为准 |
| 没有想要的分辨率 | 取决于源视频、账号和解析结果；画质上限不会产生源视频没有的清晰度 |
| 长时间显示合并 / 转换 | 等待磁盘写入和 FFmpeg 完成；检查空间，MP3 转换通常更耗时 |
| 总进度没到 100% | 查看是否有失败、取消或等待任务，不把失败视作完成 |
| 找不到文件 | 看任务详情中的最终路径，并检查当前保存位置 |
| 保存失败 | 检查目录权限、磁盘空间和文件占用情况 |

平台支持由 yt-dlp 决定，入口见 [官方支持列表](https://github.com/yt-dlp/yt-dlp/blob/master/supportedsites.md)。列出平台不代表当前网络中已逐一验证。

## 11. 升级与卸载

**安装版**：退出拾链后运行新版安装包，使用原安装目录覆盖安装；安装器会记住原路径。不要同时运行两个安装器。设置及下载独立于程序目录保存，重装会保留。若要换安装目录，先从 Windows 设置 → 应用 → 已安装的应用 → 拾链卸载，再安装到新位置。卸载只移除随包程序和快捷方式，保留设置、下载及用户自己放入的文件。

**便携版迁移到安装版**：先退出两边程序，把旧目录的 `settings.json` 复制到 `%LOCALAPPDATA%\LinkHarbor\`（如已有设置，先备份）。旧下载文件不自动搬迁，可在主界面把保存位置指向原目录；移动文件前确认没有下载任务。

**便携版**：

升级前停止任务并退出旧版。下载新便携包，解压到新目录，确认能运行后再迁移需要的设置和下载文件；不要覆盖混用不同版本的 `tools` DLL。旧目录可以自行删除，但先保留自己的下载内容和设置。

便携版退出后删除程序目录即可移除；自选目录中的下载文件不会随程序目录一起删除。安装版和便携版均不安装后台服务。此版本将最新多任务功能统一为 v1.0.1。

## 12. 从源码构建与测试

```powershell
git clone https://github.com/Xueluoa1/linkharbor.git
cd linkharbor
git checkout master
# 将正式便携包中的完整 tools 文件夹复制到这里
.\check-tools.ps1 -VerifyHashes
.\build.ps1
.\test-all.ps1
.\package.ps1
```

构建依赖和组件来源见 [tools/README.md](../tools/README.md)。测试按顺序执行核心、批量、GUI 检查，使用本地 HTTP 素材；GUI 需要可用的 Windows 桌面。打包脚本只收集明确列出的程序、依赖和说明，不打包个人配置、Cookie 或下载内容。

完整 EXE 的补充打包源码位于 `master` 分支及 Release 的 `LinkHarbor-v1.0.1-Compact-Source.zip`，不改变原有应用版本或标签。在该源码目录准备好 `tools/` 后运行：

```powershell
.\package-singlefile.ps1
.\test-singlefile.ps1
```

生成 `dist/LinkHarbor-v1.0.1-Windows-x64-Compact.exe` 及 `.exe.sha256.txt`。无需第三方安装器或联网下载组件。高级检查可使用 `完整EXE路径 --extract-only`，只展开和校验组件、不打开界面；退出码 0 表示成功。

正式安装包使用 `package-installer.ps1`，需 Inno Setup 6.7.3 编译器；补充源码在 `master` 和 Release 的 `Setup-Source.zip`。构建、测试与参数详见 [安装包构建](安装包构建.md)。
